# Athlete provider profiles — review and deployment

Review `202611150001_athlete_provider_profile.sql` separately, then test it against a disposable Supabase database with the preceding migrations applied. Run `supabase/tests/athlete_provider_profile.test.sql` there. After review, apply this one migration through your normal Supabase migration process (or paste the reviewed SQL into the project's SQL editor). Do not rerun old migrations, reset the database, or change credentials. This change has NOT been applied automatically.

The auth INSERT trigger seeds only newly created rows. The authenticated repair RPC takes no user ID and uses auth.uid(); primary key conflicts do nothing. Existing profiles are never automatically updated. Existing RLS policies and column grants remain unchanged. Metadata is display data only, never authorization data. Google, Facebook and email metadata use the same profile fields. No username is inferred or required.

Existing users: open Profile ? Edit profile ? Preview account details, review the name/photo, then Save profile. Only a blank/“Athlete” name and absent photo are suggested. A customized name, storage avatar, bio and privacy setting are preserved. Because old records have no customization provenance, even a generic name is changed only after an explicit save. Photo URL accepts HTTPS; existing private Storage keys still work. An empty photo removes it. Provider photos may expire or reject loading; the screen falls back to the default icon without changing the saved value.

Before applying the migration, existing profiles can already preview/save metadata with the client fix. New profiles created by the old trigger will need that explicit action until the trigger migration is applied. A genuinely missing profile requires the reviewed repair RPC; the client never attempts an insert that existing RLS disallows.

Manual verification on a test project: sign in with a new Google account and verify profiles.id equals auth.users.id, name/photo are seeded, and repeated login does not change them. Edit name/photo/bio with an empty username, save, refresh, sign out and sign in; verify persistence. Repeat with an existing generic profile, a customized profile, and email/Facebook accounts when those providers are configured. Confirm workouts and club memberships are unchanged. Concurrent edits to changed fields should show a refresh warning rather than overwrite each other.
