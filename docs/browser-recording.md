# Foreground browser recording

Start now requests browser location permission and waits for an accurate, recent fix before creating a workout. On HTTPS or localhost, browsers with Geolocation and IndexedDB can record real foreground location updates. An insecure origin, unsupported browser, denied permission, unavailable GPS, poor accuracy or storage failure produces an explanation. No demo coordinates or distances are generated by application code.

The existing dark Record layout, sports, metrics and tabs remain. Start, Pause, Resume, Finish and confirmed Discard work on web. Metrics use the same real-measurement distance, moving-time, pace and elevation calculations as native recording. Elevation remains unavailable when the browser does not provide reliable altitude measurements.

Accepted GPS samples are saved in IndexedDB using the existing Workout model. The app's shared store refreshes after changes, so completed recordings appear in Activities and Home/Profile statistics and survive refresh. Signed-in recordings retain the Supabase user ID. Existing opt-in Profile → Sync & restore workouts and automatic retries use the same owner-scoped upload architecture; local-only recordings are not silently assigned or uploaded to a signed-in account.

The existing MapLibre/DiscoveryMap now renders accepted recording segments. Interactive base maps require the existing restricted public MapTiler configuration; without it, the screen explains the missing configuration and shows an actual recorded route preview. GPS recording and saving do not depend on map tiles. Pauses and missing-fix gaps are not joined into a route.

Browser recording is foreground-only. Switching tabs, hiding the page, GPS errors or a gap in valid readings pauses recording and stops its watcher. Resume explicitly requests location again and starts a separate segment. Reload/recovery pauses at the last saved GPS evidence; time spent suspended is not assumed to be activity. Keep the browser visible and device awake. Clearing site data removes unsynced recordings. Native Android/iOS builds remain the way to use background tracking; the web UI does not offer that unsupported option.

## Verify in a browser

1. Open the app over HTTPS or localhost, go to Record, select a sport and press Start. Allow location when prompted. Start should visibly wait for GPS; denied/poor GPS should display a useful message without creating an empty workout.
2. Move outdoors. Check accepted fixes, distance, time, speed/pace and the map/route preview. Stationary jitter must not create artificial distance.
3. Pause, move, then Resume. The pause gap must not add distance. Finish, then check Activities, Home and Profile. Refresh to verify persistence.
4. Start another recording, hide the tab and return. It should be paused. Resume or discard it; confirm Discard removes only the unfinished workout.
5. Test permission denial, unsupported geolocation and revoked/unavailable GPS. Check that an explanation appears and no fake route or workout is created.

## Automated validation and device limits

`npm run check` covers TypeScript, lint, existing tracking/sync tests, new web-recorder lifecycle/error tests and unchanged native-recorder regression tests. The recording Playwright suite exercises real browser IndexedDB, application controls/storage/statistics and reload recovery with explicitly isolated Geolocation test fixtures. A separate configured-map adapter test verifies the exact GPS geometry reaches MapLibre. Test-only coordinates are never bundled into the app.

Web, Android and iOS exports check platform resolution and bundling. These checks do not replace outdoor device testing: actual browser permission prompts/provider accuracy, Android/iOS GPS, background permissions, battery restrictions, screen locking and physical movement still require real devices. Live Supabase upload/restore should be checked in your configured account using the existing sync controls; automated tests mock cloud operations.

Changed implementation files: `services/recorder.web.ts`, `services/database.web.ts`, `features/recording/browser.ts`, `components/RecorderMap.web.tsx`, and `src/app/(tabs)/record.tsx`. `components/TrackMap.web.tsx` also has corrected copy directing users to real browser recording. Native recorder/database implementations, OAuth, database schema and credentials are unchanged.
