# Route studio

Route studio reuses DiscoveryMap, the pinned MapLibre browser loader, the shared MapTiler streets/outdoor styles and EXPO_PUBLIC_MAPTILER_KEY. No dependencies or providers were added. The existing react-native-maps service is retained for Android/iOS; GPS recording components and services are unchanged.

Plans connect waypoints directly and show approximate straight-line kilometres. They do not establish road access, safety, elevation or travel time. No road-following backend is configured. MapTiler advertises Directions as a beta requiring access: https://www.maptiler.com/routing/ . A map tiles key alone does not establish working routing access. Enable road-following only after configuring and validating an entitled MapTiler routing service or an appropriately licensed backend, including its response geometry, supported travel profiles, errors and access terms. No public demo routing endpoint is used.

Plans remain in the existing `routes` key in device storage, separate from workout storage. Each new save appends a new ID, title, waypoints, LineString geometry, distance in metres, straight-line planning mode, plan kind and ISO creation date. Opening and saving creates a copy. Legacy plans are read with recomputed geometry and distance; their unknown creation date remains null. Invalid or unsupported stored plans block mutations to preserve their data. Mutations reread storage and use the existing process-local serial queue; this does not provide locking across browser tabs.

Base-map tiles require internet. Missing keys, loader/provider failures and offline status are explained in the web panel. Native builds retain the existing Android service configuration requirement and provide loading timeout/retry feedback. Physical-device gestures and actual MapTiler tiles require device/live-service verification. Browser adapter tests exercise lifecycle and planner behavior using an explicitly isolated test double, not geographic rendering.

Validation commands (Windows): `npm.cmd run typecheck`, `npm.cmd run lint`, `npm.cmd test`, `npx.cmd expo export --platform web`. Run `maps.spec.ts` and the missing-key planner test against the normal export without a map key. To exercise adapters, export with `EXPO_PUBLIC_MAP_DEVELOPMENT=true`, then run `npx.cmd playwright test planner.spec.ts maps-adapter.spec.ts` with `MAP_ADAPTER_TEST=true`. Restore the normal export afterward. The preview server is `node scripts/preview-server.mjs`.

Implementation verification: TypeScript and lint passed; 163 unit tests passed, including Android/iOS planner adapter and GPS recorder regression tests. Four browser adapter cases passed at 390/1440 widths, three missing-key/offline/navigation cases passed, and the loader-failure recovery browser case passed. Web export passed and was restored with the configured environment. The opt-in live planner test (`MAP_LIVE_TEST=true`, grep `live MapLibre`) failed because the MapLibre library could not load in the browser; the panel displayed its connection/retry explanation. Actual tile rendering and physical-device gestures remain unverified.
